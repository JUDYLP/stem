# Unscripted｜决策记录

2026-11-14 v2。本文是已采用的执行方案；不表示产品实现已完成。

## D01｜零代码基线

采用：全部从零创建，无旧数据兼容任务。依据为用户确认。检查目录仅用于防止覆盖，不进行假定旧仓库审计。只有用户提供真实资产并明确纳入时重开。

## D02｜纯前端静态架构

采用：HTML/CSS/原生 JS、JSON 题库、localStorage 非敏感自评；不加后台、代理、登录或数据库。原因：降低部署与集成负担，匹配一周窗口。代价：浏览器 CORS 和 Key 暴露风险；Live 可降级。开发 Subagent 不属于产品架构。

## D03｜Sol 主执行，Astra 按需审查

采用：Sol 串行完成日常编码、调试、测试、部署；Astra 负责架构冻结、重大争议和最终审核，复杂故障按触发条件介入。没有技术任务非某一模型不可，所谓“必须 Astra”是项目质量门职责；不可用时如实记录替代审核，不能阻断无争议保底工作。

原因：主 Agent 持有完整上下文并频繁运行，常驻 Astra 会增加高成本调用；任务小，重复分发也可能比直接做更贵。不将 API 定价当成订阅额度规则。

事实边界：当前工具暴露了三种指定模型 ID，尚未实测调用权限。不要因角色提示词宣称模型已切换。重开条件：实际工具不支持选模，或主模型不可用；先用已验证可用替代者，不为测试权限启动空任务。

## D04｜先手动闭环和英文 Demo，后 Live

采用：最少 3 题；手动 Retry 和独立英文 Demo 提前到 11/16 目标。API Spike 早做，Live 集成晚于核心稳定。原因：API 是外部依赖，国际评委无 Key 体验是提交关键路径。6 题是目标，20 题、复杂视觉和统计全部推迟。

## D05｜API 限时验证与诚实降级

采用：实际 HTTPS origin 的浏览器成功才算通过；Key 由用户在界面安全输入。60–90 分钟是主动排查时间盒，不反复撞限流；缺 Key 记未测试，认证失败不等于 CORS 失败。浏览器泛化网络错误不足以确定根因，记录可观察证据而非猜测。

Live 不成立就移出正式演示，保留 manual+Simulated，披露 AI 集成缺口。禁止为了“AI 看起来存在”伪造反馈；开发用 AI 与产品真实 AI 分开陈述。没有批准不增加代理。重开条件：有经验证的低成本浏览器接口且未到功能冻结。

## D06｜自评是唯一正式状态来源

采用：AI 只建议；题目×层级只保存最后 pass/review，不计算历史失败或能力增长。复习单只导出当前 review。AI 摘要需同意保存，必须来自当前题层和当前回答的真实响应；回答变化使旧诊断失效。

代价：缺少纵向学习统计；收益：状态和叙事可验证。更改持久化契约要记录 schema 决策，禁止在局部代码里静默改变。

## D07｜安全和模拟隔离

采用：Key 仅内存、不进日志/仓库/视频；动态文本仅作为文本；模型 JSON 严格校验；引用必须是输入原句。Demo 独立状态且持续标记，不写正式记录。切换题层中止或忽略旧请求，Retry 不自动调用收费接口。

## D08｜并行默认关闭

采用：运行中的子 Agent 总数最多 2；通常 0 或 1；全部禁止递归。首个可运行、可部署 MVP 验收前不委派。后续只做文件互斥、输入输出确定的可选任务。任务能由 Sol 一次完成则不拆分。

原因：省成本关注输入、输出、返工和协调总量，不追求 Agent 数量。主执行者独占集成、Git、浏览器、发布与计划文档。可选候选文件不直接变成标准题库。若并行发生文件冲突或主线等待，立即改回串行，不增加协调框架。

## D09｜上下文采用单一维护源

采用：项目建立后只更新 docs/planning 三文件；MASTER_PLAN 稳定契约、TASKS 进度和具体卡片、DECISIONS 取舍原因。旧交接书归档作来源，不反复搬进上下文。子 Agent 用最小任务包，不继承完整聊天。

不做自动摘要流水线、向量数据库、Agent 调度器或额外服务。每卡简短状态和精确文件范围足以交接。

## D10｜断网要求的边界

采用：首版 Demo 在页面资源加载完成后断网仍可运行，且全程不发 AI 请求。纯静态站首次无缓存离线打开不能保证可用；不得将前者宣传成任意设备首次离线可访问。

若比赛现场需完全离线启动，提供本地完整静态文件和 HTTP 服务作为应急。Service Worker/PWA 离线缓存推迟，避免缓存更新复杂度影响提交。

## D11｜截止保护与证据

采用：11/18 晚冻结功能，11/20 争取正式提交，11/21 处理补救。本轮已核验官方 Devpost：截止 11/21 23:59 EST、视频≤6分钟、11/24 EST 展示等，来源与边界见 MASTER_PLAN §9。Discord 具体安排未取得；用户尚未加入。T01/T12 检查变更，不再将已核实信息写为完全未知。

完成必须有真实浏览器和命令结果；文案、试用反馈、API 成功、提交确认不能由模板补造。技术审核由 Astra/替代审查者给结论，正式身份声明与提交内容由用户确认。已有明确发布授权时不重复询问。

## D12｜最终审核只检查可交付风险

采用：审查当前发布 commit、QA 报告、实站链接、README、视频/提交材料的一致性，以及无 Key、隐私、模拟标记、可访问性。无新证据不重新设计架构、不要求重写已通过模块。

停止条件：崩溃、Key 泄漏、模拟冒充真实、提交材料缺失等必须修复；装饰、扩容、统计不得挡住提交。Astra 接收简短证据包，仅按风险查看相关源码。

## D13｜CORS 失败不自动等于参赛 AI 例外

官方明确的无产品 AI 例外条件是缺 API credits，未明确将 CORS 失败列为同等情形。采用：无 Live 时保持产品可运行，准确披露原因；只有 CORS 受限时向主办方确认适用性，不承诺保底版必定被认可。不得谎称没有 credits，也不因风险改造为未经批准的代理。此事项不阻止本地开发。

## D14｜提示词编号与执行顺序分离

保留附件要求的 Prompt 0–7 模块编号。推荐 0→1→2→3（预览及限时 Spike）→5（仅手动闭环）→6→4（条件性 Live）→5（仅尚缺 AI 展示）→7。已完成且有有效测试证据的功能不得重复实现；Prompt 5 明确两种作用域。模块编号不是新增依赖，不让 API 阻塞 Demo。

## D15｜环境缺失的真实阻塞

Prompt 0 目标是可运行且可 commit，但 Git 未安装、无有效身份或无任何 HTTP 运行能力时不能保证完成。先完成独立文件工作，再报告最小缺口；不捏造身份、不擅自全局改配置或安装大批依赖。若当前目录属于上级仓库，只确认边界后在新项目独立初始化，不修改上级仓库。首屏按钮点击只能执行真实可用动作或明确禁用。

首批Redis题改为过期机制，采用可直接核对的官方EXPIRE说明，宽泛缓存故障分类后置。用户授权连续推进后续开发，不再沿用T00完成即停止作为后续开发限制；仍按小阶段验收和提交。人工审校未完成时页面明确标注，工程集成可以继续。
